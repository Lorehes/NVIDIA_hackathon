# HTTPS 페이지의 HTTP 폼 전송 판단 개선

2026-09-26. 사용자의 “전부 하나씩 확인하는가, URL은 최종적으로 어떻게 처리하는가”라는 지적에 따라 이번 단계는 수동 주소 추가보다 공통 판정 로직을 우선했다.

HTTPS 공식 페이지가 같은 공식 호스트의 HTTP 주소로 입력을 보내도록 되어 있어도, 공식 주소 일치 때문에 safe가 될 수 있는 빈틈을 수정했다. 페이지 연결과 입력 전송 주소의 암호화를 따로 판단한다. 일반 입력·비밀번호·숨김 값·파일 선택, 제출 버튼의 formaction 및 외부 버튼의 form 연결, base 기준 상대주소를 확인한다. 표시용 전송 주소 20개 제한 전에 관찰된 주소 전체를 검사한다. 기존 증거에 새 플래그가 없으면 기존 action_urls도 확인한다.

HTTP 전송 주소가 있으면 insecure_form_action 경고로 safe를 제한한다. 공식 신원은 별도로 유지한다. 이는 HTML에 선언된 HTTP 수신 주소를 확인한 것이며 실제 전송·브라우저 HSTS/자동 승격·서버 처리를 확인했다는 뜻이 아니다. 특정 사이트나 기관 이름 조건문을 추가하지 않았다. 검색/만족도라는 이름만으로 일반 입력 폼을 면제하지 않는다.

다른 사이트로 보낸다는 경고가 없다는 이유만으로 “페이지 안에서만 처리된다”고 단정하던 비교·상세 설명을 수정했다. 이제 표시된 전송 주소를 확인했으나 실제 전송과 서버 처리 과정은 검사하지 않았다고 안내한다.

다음에는 새 주소를 개별 등록하는 작업만 반복하지 않고, 일반 URL 판단의 미검증/정상 입력 구분과 사용자 설명을 우선한다. 실제 결과의 비교·추적용 기본 목적 레이블에는 URL 입력에서도 “안내 문자”가 남아 있어 별도 보완이 필요하다. 공식 근거 부족 자료, 명부누락·폐지·이전, 동명이 기관의 지역 식별, 다른 운영사 출처, 실제 전체 보안 시나리오 및 엄격한 총90초는 미완료다. 전체 기관 누락 없음 또는 모든 URL 안전 판단 완료를 뜻하지 않는다.
