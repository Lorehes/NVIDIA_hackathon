# 대표·일반·모바일 주소 이동 처리

## 문제

`www.naver.com` 조사 `j_d23447e33a3843e1bf400c16971fd43e`는 실제 HTTP 302로 `https://m.naver.com`에 이동했다. 기존 정책은 최초 호스트 하나만 허용하여 모바일 주소를 403 차단으로 기록했다. 입력 도메인 자체가 악성이라는 근거가 아니라 조사 범위가 너무 좁아서 생긴 차단이었다.

## 변경

- 공개 등록 도메인의 대표 주소, `www`, `m` 세 주소 사이 이동을 명시적으로 허용한다. 와일드카드는 사용하지 않는다.
- 시작 주소가 위 세 형태가 아닌 다른 서브도메인이면 기존처럼 입력 호스트만 허용한다.
- Public Suffix List의 비공개 호스팅 구역(github.io, blogspot.com 등), 알 수 없는 접미사, IP 주소는 자동 확장하지 않는다. PSL 사용 불가 시에도 확장하지 않는다.
- 추가 주소도 정책 생성 전에 내부망 DNS 결과를 검사한다. 호스트 검사만으로 접속 시점의 DNS 재바인딩까지 증명하는 것은 아니며 기존 프록시 경계를 유지한다.
- 샌드박스 정책과 검사기의 허용 목록을 일치시킨다. 정책은 GET, 80/443, 기존 Python 실행 파일로 제한한다. 검사기는 범위 밖 이동을 다음 요청 전에 중단한다.
- 안전 공간 기록에 실제 허용 주소를 표시하고, “한 곳만” 안내를 수정한다.
- 공식 여부·페이지 위험 판정 규칙은 유지한다. 이동 허용은 안전 판정이 아니다. 네이버 공식 기관 KB는 이번 수정 범위에 추가하지 않았다.

## 검증

- 전체 Python 테스트 **464개 통과**(77.50초). 기존 httpx 관련 사용 중단 경고 1개.
- 웹 타입 검사·프로덕션 빌드 통과.
- 새 테스트: 대표/www→m 정상 이동, 유사 도메인·다른 도메인·미허용 서브도메인·내부망 IP·비표준 포트 차단, 공유 호스팅 구분, 내부망으로 해석되는 추가 주소 제외, 정책 GET/포트 제한.
- 이전 조사 결과는 당시의 기록으로 보존한다. 수정 결과는 새 조사로 확인한다.

## 실제 VM 재검증

`naver.com`은 301 → `www.naver.com` 302 → `m.naver.com` 200으로 정상 이동했다. 차단 0건, 조사 중단 없음, 남은 접속 권한 0건. 공식 기관 KB가 비어 있는 대상이므로 unknown 판정은 유지된다. 검증 작업: `j_f955081046904bd1875d8f4fc3a40667`.

`www.naver.com`으로 시작한 별도 조사도 302 → `m.naver.com` 200, 차단 0건·중단 없음·잔여 권한 0건으로 완료됐다. 검증 작업: `j_fb2a4e91ba5c4fe7b9c67af6d81cad1a`. [실제 경로와 정책 기록](evidence/2026-09-25-navigation.json).

## 후속 검증 정정

이 문서의 이전 '잔여 정책 0'은 provider 접두어가 붙은 `nemoclaw_custom__job-*` 정책을 누락한 검사에 기반했다. 후속 조사에서 11개 이전 정책을 발견해 제거하고 이름 정규화·시작 시 정리·회귀 테스트를 보강했다. 현재 설계는 대표/www/m 예외 목록 대신 실제 HTTP 이동을 관찰하고 정확 호스트·공인 IP 제한을 추가한다. CDN DNS 차이 등 최신 결과와 남은 검증은 `2026-09-25-catalog-progress.md` 및 `2026-09-25-discovered-navigation.md`를 따른다.
