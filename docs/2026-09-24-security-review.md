# 프로젝트 컨셉 및 보안 개선 검토

- 검토일: 2026-09-24
- 검토 대상: 기획 문서, API, 웹 프런트엔드, 조사 스크립트, 샌드박스 제어 및 배포 설정
- 검토 방식: 소스 코드 검토, 기존 테스트 실행, 주요 경계 조건 추가 확인
- 검증 결과: 기존 테스트 106개 통과. 추가 확인에서 거짓 안전 판정과 AI 설명 검증 우회 재현
- 범위의 한계: 실제 배포 환경의 OpenShell 정책·파일 권한과 실제 모델을 이용한 공격 방어는 검증하지 않음
- 변경 사항: 검토 당시 구현 코드는 변경하지 않음

## 1. 프로젝트 컨셉

**의심 문자를 붙여 넣으면, 격리된 환경에서 링크를 대신 조사하고 누구를 사칭하는지 근거와 함께 설명하는 서비스**다.

공식 도메인, 주소 위장, 페이지의 입력 요구 사항을 비교하고, **규칙이 판정하고 AI가 설명한다**는 방향이 핵심이다. 확인된 사실, 사칭 의심 근거, 확인하지 못한 내용을 나눠 보여주는 점이 장점이다.

다만 현재 구현은 데모 단계이며, 공개 서비스로 배포하기 전에 아래 보안 문제를 보완해야 한다. 기존 테스트가 모두 통과하더라도 아래 경계 조건과 운영 환경의 보안을 보장하는 것은 아니다.

## 2. 보안 개선 사항

### 2.1. [매우 높음 · 재현됨] 확인하지 못한 사이트도 안전으로 판정

공식 도메인이라는 조건이 충족되면 조사 결과가 빠지거나 페이지 분석이 실패해도 `safe`가 나올 수 있다. 추가 확인 결과는 다음과 같다.

| 조건 | 현재 판정 |
|---|---|
| 접속·페이지 분석 결과 없음 | `safe` |
| HTML을 확보하지 못함 | `safe` |
| HTTP 404 응답 | `safe` |
| 암호화되지 않은 HTTP 접속 | `safe` |

**개선 방향**

- 안전 판정에 필요한 증거를 명시적으로 요구한다. 접속 성공, 분석 가능한 응답, 페이지 분석 완료, 리다이렉트 조사 완료 등을 검사한다.
- 필수 조건을 충족하지 못하면 `unknown`으로 처리한다.
- 공식·협력사 도메인이라는 사실만으로 페이지 전체의 안전을 보증하지 않는다. 결과 문구는 **“공식 주소와 일치해요”**처럼 확인한 범위에 맞춘다.

코드 근거: [verdict.py](../apps/api/app/verdict.py), 검토 당시 231행.

### 2.2. [매우 높음] 다른 사람의 조사 결과를 조회할 수 있는 구조

결과와 상세 기록 조회에 사용자나 세션 소유권 검사가 없다. 작업 ID는 UUID의 앞 6자리만 사용하므로 24비트에 불과하다.

ID를 알아내거나 추측하면 조사 URL과 상세 결과를 열람할 수 있다. URL에는 인증 토큰이나 개인정보가 포함될 수 있다.

**개선 방향**

- 익명 서비스라도 세션별 작업 소유권을 검사한다.
- 작업 ID는 전체 UUID 등으로 늘린다.
- 공유 기능이 필요하면 별도의 충분히 긴 비밀 토큰과 만료 시간을 둔다.
- ID를 길게 만드는 것만으로 접근권한 검사를 대체하지 않는다.

코드 근거: [worker.py](../apps/api/app/worker.py), 검토 당시 42행; [main.py](../apps/api/app/main.py), 검토 당시 133행.

### 2.3. [높음] AI가 판정의 입력 자료를 바꿀 수 있는 신뢰 경계

호스트는 샌드박스에서 받은 JSON 파일을 판정의 사실 자료로 사용한다. 조사 에이전트에는 `exec`가 있고, 파일 수정 금지는 주로 스킬의 지시문에 의존한다. 예상 밖 도구 사용도 기록만 한다.

**판정 코드가 결정적이라는 것과 판정 근거를 조작할 수 없다는 것은 별개의 문제**다. 프롬프트 주입에 성공하면 결과 파일이나 검사 스크립트 변경을 시도할 여지가 있다. 실제 배포 환경의 파일 권한까지는 확인하지 못했으며, 실제 모델을 통한 변조 성공을 재현한 것은 아니다.

**개선 방향**

- 검사 스크립트와 입력을 에이전트에 대해 읽기 전용으로 둔다.
- 결과는 에이전트가 수정할 수 없는 별도 권한의 실행기가 생성하게 한다.
- URL 분석은 호스트에서 재계산한다.
- 결과의 작업 ID, 대상 URL, 필수 필드를 대조한다.
- 도구 사용 제한은 지시문뿐 아니라 실행 권한으로 강제한다.

코드 근거: [sandbox.py](../apps/api/app/sandbox.py), 검토 당시 259행; [worker.py](../apps/api/app/worker.py), 검토 당시 129행.

### 2.4. [높음 · 운영 환경 검증 필요] 내부망 접근 방어가 호스트 문자열 검사에 의존

현재는 IP 주소와 `.local` 같은 이름을 걸러낸다. 일반 도메인이 DNS에서 사설 IP로 해석되는 경우는 검사하지 않으며, 해당 도메인을 그대로 네트워크 허용 정책에 넣는다.

검토 당시 [OpenShell 공식 문서의 SSRF 보호 설명](https://docs.nvidia.com/openshell/security/best-practices#ssrf-protection)은 정책에 명시한 정확한 호스트명이 사설 IP로 연결되는 것을 허용할 수 있다고 설명한다. 샌드박스를 사용한다는 이유만으로 내부망 접근 차단을 가정하면 안 된다. 실제 배포 버전과 정책에서의 동작은 별도 확인이 필요하다.

**개선 방향**

- 실제 연결을 수행하는 프록시 계층에서 DNS 결과와 최종 목적지 IP를 검사한다.
- 내부망 접근을 차단하고 모든 리다이렉트에도 같은 검사를 적용한다.
- DNS 재바인딩을 포함한 실제 네트워크 테스트를 수행한다.

코드 근거: [urls.py](../apps/api/app/urls.py), 검토 당시 58행; [worker.py](../apps/api/app/worker.py), 검토 당시 98행.

추가 참고: [OWASP SSRF 방어 가이드](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html).

### 2.5. [높음] 격리 정책 정리에 실패해도 다음 조사를 계속 진행

정책 추가가 서버에서는 반영됐지만 응답이 시간 초과되면, `opened`가 설정되지 않아 삭제를 시도하지 않을 수 있다. 삭제가 두 번 실패한 경우에도 경고를 남기고 공유 샌드박스를 계속 사용한다.

**개선 방향**

- 정책 상태가 불확실하면 신규 조사를 중단한다.
- 실제 적용 상태를 재조회한다.
- 정리를 확인하지 못하면 샌드박스를 폐기하고 재생성한다.
- CLI 시간 초과 시 원격 작업도 종료됐는지 확인한다.

코드 근거: [sandbox.py](../apps/api/app/sandbox.py), 검토 당시 183행과 216행; [worker.py](../apps/api/app/worker.py), 검토 당시 165행.

### 2.6. [높음 · 재현됨] AI 설명 검증이 위험한 안내를 통과

`suspected_impersonation` 판정에도 다음 설명이 검증을 통과했다.

> 문제없으니 링크를 열고 비밀번호를 입력하세요.

일부 단어, 숫자, 도메인을 검사하는 방식으로는 문장의 의미나 사실성을 보장할 수 없다. 이는 검증 함수에 해당 문장을 입력해 확인한 결과이며, 실제 모델이 해당 문장을 생성했다는 의미는 아니다.

**개선 방향**

- 제목, 위험 경고, 행동 권고는 코드의 고정 문구로 생성한다.
- AI는 검증된 근거를 쉽게 풀어 설명하는 범위로 제한한다.
- 각 설명이 어떤 근거를 사용하는지 연결한다.

코드 근거: [explain.py](../apps/api/app/explain.py), 검토 당시 93행.

### 2.7. [높음] 반복 요청으로 자원과 비용 소진 가능

일반 조사의 대기열 제한은 조회와 등록이 분리돼 동시 요청으로 초과할 수 있다. 재생 모드는 대기열 제한 전에 요청마다 새 스레드를 생성한다. 클라이언트별 요청 제한도 보이지 않는다.

**개선 방향**

- 재생 모드까지 포함한 공통 실행 한도를 둔다.
- 대기열 용량 확인과 작업 등록을 원자적으로 처리한다.
- 세션·IP별 요청 제한과 모델 호출 예산 상한을 둔다.
- 요청 본문 크기는 JSON을 전부 읽기 전에 제한한다.

코드 근거: [main.py](../apps/api/app/main.py), 검토 당시 98행; [worker.py](../apps/api/app/worker.py), 검토 당시 271행.

### 2.8. [높음] 민감한 문자와 URL의 보관·외부 전송 최소화 필요

문자 원문과 URL을 SQLite에 저장하지만 자동 삭제가 없다. 운영 샌드박스의 작업 폴더를 삭제하는 절차도 보이지 않는다. 임베딩 검색을 사용하는 경우에는 입력의 앞 1,000자가 외부 API로 전달된다.

**개선 방향**

- 원문 보관을 최소화하고 짧은 보관 기간과 자동 삭제를 적용한다.
- 호스트 저장소뿐 아니라 샌드박스 작업 자료에도 삭제 정책을 적용한다.
- 외부 모델에는 전화번호, 인증번호, URL 토큰 등을 제외한 필요한 정보만 전달한다.
- 사용자에게 보관과 외부 전송 범위를 알린다.

코드 근거: [db.py](../apps/api/app/db.py), 검토 당시 18행; [kb.py](../apps/api/app/kb.py), 검토 당시 128행; [sandbox.py](../apps/api/app/sandbox.py)의 운영 조사 흐름.

## 3. 제품 측면 개선 사항

### 공식 주소 여부와 위험 행동을 별도로 표시

공식·협력사 도메인에서도 비정상적인 정보 요구는 경고해야 한다. 현재는 이들 도메인에서 목적 불일치 검사를 제외한다. 도메인 일치와 페이지의 위험 행동을 별도 축으로 보여주는 것이 더 정확하다.

### 문자 전체와 링크 한 개의 결과를 구분

지금은 첫 링크만 조사한다. 정상 링크 뒤에 악성 링크가 붙은 문자에 전체적으로 안전하다는 인상을 주지 않도록, 미검사 링크가 있음을 결과 제목 가까이 표시한다.

### 데모 밖에서 성능 측정

현재 KB는 가상 브랜드 두 개다. 실제 기관 자료의 출처, 검증일, 갱신 주기를 관리하고 다음 사례로 오탐과 미탐을 측정해야 한다.

- 정상 협력사와 외부 결제·인증 서비스
- 단축 URL과 여러 단계의 리다이렉트
- 접속 실패, 빈 응답, 페이지 분석 실패
- 프롬프트 주입과 조사 결과 변조 시도

## 4. 권장 작업 순서

해커톤 일정에서는 다음 순서로 먼저 보완한다.

1. 거짓 `safe` 판정 차단
2. 조사 결과 접근권한 검사
3. 격리 정책 정리 실패 시 신규 조사 중단
4. 행동 권고의 고정 문구화

공개 서비스 배포 전에는 조사 결과의 무결성, 내부망 접근 차단, 요청·비용 제한, 민감정보 보관 및 삭제까지 보완하고, 실제 OpenShell과 모델을 이용한 공격 방어 검증을 수행해야 한다.

## 5. 조치 결과

검토 당시 지적한 항목을 코드에 반영했다. 기존 106개에 새 테스트를 더한 **144개 테스트가 통과**한다. 실제 OpenShell·모델·프록시가 없는 환경이라 그 부분은 가짜 실행기와 로컬 흉내로만 검증했다.

| 항목 | 상태 | 반영 내용 |
|---|---|---|
| 2.1 거짓 `safe` | 완료 | `verdict.verification_gaps()`가 안전 판정에 필요한 증거를 검사한다. 조사·분석 결과 없음, 접속 없음, HTML 없음, 2xx가 아닌 응답(404, 이동 횟수 한도에서 끊긴 3xx 포함), 차단·오류가 있는 이동 경로, 평문 HTTP(중간 이동 포함), 인증서 미검증 중 하나라도 있으면 `unknown`이다. 결과 문구도 "주소가 공식 주소와 일치해요"로 확인한 범위에 맞췄다. |
| 2.2 결과 열람 | 완료 | 작업 ID를 128비트 전체로 늘렸다. Next 서버가 httpOnly 세션 쿠키를 발급해 `X-Session-Id`로 전달하고, API는 해시만 저장해 소유자를 검사한다. 남의 작업은 존재 여부도 숨기려고 404를 돌려준다. 기존 DB의 소유자 없는 작업은 열리지 않는다. |
| 2.3 입력 무결성 | 일부 | 주소 유사도는 호스트가 다시 계산해 쓴다. 샌드박스의 `parse_url`·`fetch_chain`이 요청 주소와 다르면 결과를 버리고 `unknown`으로 처리한다. **미완료:** 검사 스크립트·결과 폴더의 읽기 전용 권한과 별도 권한의 실행기는 OpenShell 정책 작업이라 코드로 검증하지 못했다. |
| 2.4 내부망 접근 | 일부 | 운영 모드에서 정책을 열기 전에 DNS 결과를 확인해 사설·루프백·링크로컬 등으로 해석되면 접속하지 않고 `internal_address` 위험 신호로 남긴다. **미완료:** 접속 시점의 DNS 재바인딩과 리다이렉트별 IP 검사는 실제 접속을 맡는 프록시 계층에서 해야 한다. |
| 2.5 정책 정리 | 완료 | 정책 추가가 시간 초과·오류여도 정리를 시도한다. 제거 성공 여부는 종료 코드가 아니라 `policy list` 재조회로 확인한다. 확인하지 못하면 샌드박스를 격리해 `sandbox_unsafe`로 새 조사를 막고, 다음 요청에서 정리를 다시 시도해 확인되면 해제한다. `/api/health`에도 표시된다. **미완료:** 샌드박스 폐기·재생성과 CLI 시간 초과 시 원격 작업 종료 확인은 실제 명령을 확인하지 못해 넣지 않았다. |
| 2.6 AI 설명 | 완료 | 제목·경고·행동 권고·행동 목록·확인하지 못한 내용은 항상 코드의 고정 문구다. 모델은 `detail`·`confirmed_facts`·`suspicion_evidence`만 쓰며, 지시형 어미나 안심 문구가 있으면 설명 전체를 버린다. 의심 근거 수는 실제 위험 신호 수를 넘지 못한다. **미완료:** 문장별로 어떤 근거를 썼는지 연결하는 기능. |
| 2.7 반복 요청 | 완료 | 대기열 여유 확인과 등록을 한 잠금으로 처리한다(잠금을 빼면 실패하는 동시성 테스트 포함). 재생 모드 스레드 수를 제한한다. 세션·클라이언트 IP별 분당 제한을 두었다. 본문은 읽는 도중에도 크기를 검사한다. **주의:** IP 제한은 앞단 프록시가 `X-Real-IP`를 덮어써 줄 때만 의미가 있다. 모델 호출 예산 상한은 넣지 않았다. |
| 2.8 보관·전송 | 일부 | 끝난 조사는 24시간(`RETENTION_HOURS`) 뒤 원문·결과와 함께 삭제한다. 어떤 경로로 끝나도 호스트 작업 폴더를 지우고, 샌드박스 안의 작업 폴더도 회수 뒤에 삭제한다. 임베딩 API로는 URL과 4자리 이상 숫자를 지운 문자만 보낸다. **미완료:** 사용자에게 보관·외부 전송 범위를 알리는 화면 문구. |

### HTML 파서 교체 (5라운드 이후, 사용자 결정)

3~5라운드 지적이 줄지 않은 근본 원인(직접 만든 HTML 해석기와 브라우저의 차이)을 없애려고 페이지 분석을 **html5lib**(HTML5 명세를 따르는 토크나이저·트리 빌더)로 바꿨다.

- **구조:** 문자셋 판정(`_decode`: BOM → HTTP 헤더 → 인코딩 사전 검사, WHATWG 이름만, 자체 ISO-2022-JP 디코더)은 그대로 두고, 디코딩한 문자열을 `html5lib.parse(..., treebuilder="etree", namespaceHTMLElements=False, scripting=True)`에 넘겨 트리를 얻는다. `_Doc`이 트리를 반복(비재귀) 순회하며 폼·컨트롤·스크립트·핸들러·능동 콘텐츠 주소·`<base>`·`srcdoc`를 뽑는다. 원문 종료 태그, 자기 닫음 표기, 폼 포인터, `select`·`table`·SVG·MathML 같은 외부 콘텐츠, 주석 변형 등은 라이브러리가 명세대로 처리한다. `form` 속성에 의한 소유는 여전히 `_Doc.form_groups()`가 처리한다.
- **fail-closed:** html5lib가 없거나(`html5lib missing`), 태그 시작 부호가 15만 개를 넘거나(`too many tags`), 문서 하나에 8초를 넘기면(`parse timeout`, 데몬 스레드) 분석 실패(`ok: false`)로 처리해 `safe`가 나오지 않는다. 적대적 `<b>` 10만 개는 23초가 걸려 이 제한이 필요했다. 1MB 근처의 보통 페이지는 약 0.5초다.
- **알려진 한계:** html5lib 1.1은 `<template>`를 명세대로 읽지 못해(안의 `<form>`이 폼 포인터를 남긴다) `template`이 있으면 `(unmodeled)`로 표시해 `safe`를 막는다. 브라우저의 최신 명세 변경(예: 새 `select` 파싱)과 라이브러리 버전 사이의 차이는 남을 수 있다.
- **배포:** `apps/api/requirements.txt`와 `infra/scripts/prepare-sandbox.sh`에 html5lib를 추가했다(샌드박스에도 설치해야 한다).
- **검증:** `tests/test_html5_parser.py` 30개(원문 종료 태그·SVG·`select`·폼 소유·시간 제한·라이브러리 부재)를 더해 **369개 통과**.

### 진행 상태 (2026-09-25 기준)

- **완료:** 1라운드(`fe53b26`), 2라운드(`12cc143`), 3라운드(`888ee29`), 4라운드(`4d0d917`), 5라운드(`d6f015d`), HTML 파서 교체(이 커밋). 테스트 369개 통과.
- **수렴하지 않는 이유:** 3~5라운드 지적이 15·12·12건으로 줄지 않는다. 대부분 직접 만든 HTML·URL·문자셋 해석기가 브라우저와 갈리는 지점이다. 근본 대응은 HTML5 트리 빌더(html5lib 등)와 WHATWG 디코더를 쓰는 것인데, 새 의존성이 샌드박스 환경에 들어가야 하고 1MB 페이지에서의 속도 검토가 필요하다. 그때까지는 애매하면 `safe`에서 빼는 방향(fail-closed)으로 막아 왔다.
- **6라운드(중단):** 점검을 요청했지만 Codex가 "cybersecurity risk"로 요청을 막아(`Turn failed`, Trusted Access for Cyber 프로그램 안내) 지적을 받지 못했다. 막히기 전 중간 메시지에서 원문 종료 태그 처리, SVG 파싱, `select`의 암묵적 닫힘 쪽에서 `safe`가 나오는 탐색 결과가 있다고만 언급했고 세부는 없다(확인되지 않은 힌트). 수정한 것은 없다.
- **다음:** 6라운드를 이어서 진행한다(6라운드부터 low는 고치지 않고 기록만 한다). 다시 요청하기 전에 이 차단을 어떻게 다룰지 정해야 한다. 종료 조건은 Codex가 더 이상 지적하지 않는 것이며 라운드 수 상한은 없다. 6라운드부터 나오는 low는 고치지 않고 [deferred 파일](2026-09-24-security-review-deferred.md)에 기록한다.
- **설계상 받아들인 한계:** JavaScript를 실행하지 않으므로 `safe`는 "공식 주소이고, 신뢰 도메인 밖으로 나가는 이동·능동 콘텐츠가 감지되지 않았다"는 뜻이다. 외부 스크립트를 쓰는 실제 공식 사이트는 `unknown`이 될 수 있다. 모델의 설명 문장은 코드가 만든 검증 문장의 어절과 인접 어절 쌍으로 제한되므로, 새 표현을 쓰면 템플릿 설명으로 대체되는 경우가 늘어난다.
