# 표준자료 지역 정보 보존과 갱신 후보 분리

2026-09-26. 기존 보건기관·대학 표준자료 수집기는 이름/홈페이지/유형/기준일/출처만 저장해 시도·시군구 등의 문맥을 잃었다. 따라서 남은 반송2행·북면·백산 등의 동명이 지역을 현재 저장 자료만으로 구분할 수 없다. 공식 원자료 설명과 열 목록을 조회해 필드를 확인했다. 전체 데이터 다운로드는 수행하지 않았다.

출처: [전국보건기관표준데이터](https://www.data.go.kr/data/15107750/standard.do), [전국대학및전문대학정보표준데이터](https://www.data.go.kr/data/15107736/standard.do). 다운로드 열 목록의 제공기관코드/제공기관명은 자료를 제공한 기관을 뜻하며 개별 학교/보건소의 고유 ID로 간주하지 않는다.

`scripts/catalog/collect_education.py`의 standard 경로를 변경했다. 공식 열 코드와 설명이 함께 일치하는 시도/시군구·소재지·기관 유형·대학 분교 구분·제공기관 필드를 `source_context`로 보존한다. 기관명을 다듬거나 홈페이지 오기를 교정하지 않고, 제공기관 코드를 `source_id`로 승격하지 않는다. 담당자/전화번호/알 수 없는 열은 저장하지 않는다. 열의 의미가 달라지거나 값이 구조화 객체인 경우 각각 해당 문맥을 채택하지 않거나 수집을 거절한다.

새 표준자료는 활성 원자료 대신 `kb/sources/refresh_candidates/<자료집>.json`에 저장한다. 후보에는 기존 활성 자료 해시, 보완 설정 해시, 새 자료/해시, 동명이 개수와 새 자료에서 비활성화되는 기존 보완 목록이 포함된다. 활성 원자료 및 검토 보완을 자동 변경하지 않는다. 불완전/빈/형식 불량 응답은 이전 후보도 보존한다. 출력은 직렬화 검증 후 임시 파일을 통해 교체한다.

후보 검토 시 기준 해시를 다시 대조하고 지역·주소와 공식 기관 근거로 각 보완을 재검토해야 한다. 해시만 새 값으로 바꾸거나 이름이 같다는 이유로 기존 주소를 자동 이관하지 않는다. 자료 행이 없어졌다는 이유만으로 폐지로 판정하지 않는다. 검토가 완료된 원자료/보완을 반영하고 카탈로그 생성 및 관련 검증을 수행하는 절차는 별도다. 앱과 카탈로그 빌더는 후보 디렉터리를 읽지 않는다. 이번 변경은 표준자료 두 종류에 한정하며 NEIS 수집 경로는 바꾸지 않았다.

검증: 외부 통신을 하지 않는 모의 HTTP 응답으로 정상/동명이/제공기관 코드 구분/보완 해시 변경/미완성 및 잘못된 응답/원문 보존을 확인하는 새10개를 추가했다. 기존 원문해시·보완 검사와 함께34개가 로컬1.03초에 통과했다. 코드 구문 검사도 통과했다. 활성 카탈로그·coverage·보건 원자료·대학 원자료·보완 설정5파일은 변경 전후 SHA-256이 일치한다. 전체 앱 테스트를 반복하거나 새 VM 검사를 실행하지 않았다.

실제 새 원자료/후보는 생성하지 않았으므로 기존 누락 행의 지역 정보가 복원된 것은 아니다. 다음 갱신 주기에 사용한다. 현재 로컬22,145레코드/16,282호스트·제외2,390·보완190과 보건 미제공5행은 불변이다. VM의 마지막 검증은22,120/16,282·제외2,415·보완165다. 검색 분류 코드와 카탈로그25건에 더해 이번 수집기 변경도 VM 미반영이다. SSH 인증 상태 변화가 없어 동일 연결/SSO를 재시도하지 않았다.

재개: 기존 검색 분류 배포/대기25건 자료 반영 순서를 보존한다. 이번 수집기는 증거 JSON의 이전/현재 코드 해시와 원격 파일을 대조해 반영하고 새 test_standard_refresh.py 및 기존 보완 검사를 VM에서 실행한다. 배포 과정에서 수집기 전체 실행으로 원자료를 다시 받지 않는다. 수집기 코드는 샌드박스 런타임과 별개이며 API 재시작이나 통신권한 확대가 필요 없다. 실제 갱신 적용은 갱신 주기·공식 근거 검토 후 진행한다.
