# 공통 조사 시간 예산과 실제 실패 복구

2026-09-26. 단계별 시간 제한을 더하면 전체90초를 넘을 수 있었고, 주소 이동 추적도 별도90초 예산을 갖고 있었다. 이제 워커가 작업을 시작할 때 단조 시계로 하나의90초 예산을 만든다. 큐 대기는 포함하지 않는다. 마지막15초는 통신 권한 회수·작업 파일 정리에 예약하고, 조사·이동 추적·설명·DNS·임베딩 대기는 앞선75초의 남은 시간을 공유한다.

OpenShell 명령의 로컬 대기와 명시된 원격 `--timeout`을 함께 남은 시간으로 줄인다. 남은 시간이 부족하면 새 명령을 시작하지 않는다. 기존 단계별 상한도 유지한다. 시스템 시각 보정이 예산을 늘리지 않으며 워커의 소요 시간도 단조 시계로 측정한다.

DNS/임베딩처럼 소켓별 제한만으로 총 대기시간을 묶지 못하는 읽기는 최대4개의 제한된 읽기 스레드에서 기다린다. 기한을 넘긴 응답은 호출자에게 반환하지 않고 권한 승인이나 KB 벡터 갱신에 사용하지 않는다. 이 장치는 권한 변경 명령에는 사용하지 않는다. 읽기 자체가 OS에서 늦게 끝날 수 있으므로 읽기 스레드가 즉시 종료됐다고 주장하지 않는다. 슬롯이 가득 차면 새 읽기도 거절한다.

정리 단계에서는 예약 시간을 사용할 수 있다. 정책이 실제로 사라졌는지 확인하지 못하면 `residual_policy`와 격리 상태를 유지하며, 미완료로 표시한다. 원격 파일 정리가 실패하면 기존 보류 목록에 남겨 다음 사용 전에 재시도한다. 정리 실패를 정상 완료로 반환하던 경로도 수정했다. 원격 OpenShell 종료코드124는 일반 에이전트 오류 대신 시간 초과로 표시한다. 판단 근거나 통신 허용 범위는 넓히지 않았다.

이 예산은 하드 실시간 SLA가 아니다. OS 스케줄링, 프로세스 종료 및 로컬 결과 저장의 작은 오버헤드까지90.000초 이내라고 보장하지 않는다. 큐 대기 시간도 별도다. 단순히 모든 단계의 제한시간을 더해90초라고 표현하지 않는다.

검증: 처음 추가한8개를 포함해 로컬 전체800개/43.24초·VM전체800개/70.19초 통과. 실제 지연 시험에서 발견한 종료코드124 안내 수정에2개 회귀를 추가한 뒤 관련61개가 로컬0.50초·VM0.77초에 통과했다. 마지막 두 테스트 추가 후 전체802개를 다시 실행했다고 표현하지 않는다. 기존 Starlette 사용 중단 경고1개는 유지한다.

실제 시험은 API 작업이 없는 상태에서 서비스를 잠시 정지하고 별도 시험 작업을 생성했다. 조사 명령만 원격 `sleep 40`으로 대체했으며 실제 모델의 모든 실패 양상을 검증한 것은 아니다. 공통 예산을30초(조사15+정리15)로 축소하여 원격 기한과 실효 정책 회수·로컬/원격 자료 정리·서비스 복원을 확인했다. API는 실패 여부와 관계없이 finally에서 복원한다. 원격 종료코드124의 안내 수정 뒤 같은 시험을 다시 수행하고 파파고 실제 조사로 정상 흐름을 확인한다. 최종 재검증은16.382초/agent_timeout/권한잔여0/정리보류0/서비스정상이며, 복구 후 파파고는16.957초/공식신원 확인을 유지했다. 최종 수치와 해시는 `docs/evidence/2026-09-26-investigation-budget.json`에 기록한다.
