# 검색 입력과 범주 선택을 함께 가진 폼 분류

2026-09-26. 달성군 실제 조사에서 검색 text 입력과 범주 select가 섞인 폼3개를 일반 입력으로 분류했다. 기존 검색 예외는 type=search 입력이 하나 이상 있어야 했고 select를 허용하지 않아 같은 호스트의 미등록 검색 처리 경로에도 주의 경고가 남았다.

분류기는 다음 구조를 함께 확인한다. 특정 사이트명/URL/기관 예외는 추가하지 않았다.

- 기존 type=search 입력 또는 검색 설명과 검색용 name/id를 함께 가진 단일 text 입력이 있어야 한다. name/id의 query·q·keyword·search는 입력 목적을 보조하는 구조 단서이며 그 자체로 안전/공식 여부를 증명하지 않는다.
- 부가 select는 검색 설명이나 search 식별자가 있고 실제 option이1~50개인 단일 선택 컨트롤이어야 한다. 옵션 값은 저장하거나 출력하지 않는다. 50개는 검사기 정책 한도이며 HTML 표준의 최대값이 아니다.
- 민감 입력·파일·textarea·이름 없는 추가 입력·모호한 선택 컨트롤·선택만 있는 폼은 검색 예외로 넣지 않는다. 검색 label만으로 허용하지 않는다. type/title/autocomplete 등에 민감 정보 표시가 있으면 검색 예외를 적용하지 않는다.
- 폼과 모든 제출 버튼의 전송 주소가 같은 scheme/hostname/port에 속해야 하며 GET 또는 POST 하나로 일관되어야 한다. 다른 하위호스트/포트/HTTP·외부 버튼·혼합 메서드는 기존 경고를 유지한다. 다른 폼에 연결된 입력과 별도 위험 폼도 검사한다.

인식 결과는 same_origin_search 힌트다. 기존 search_only나 입력 유형은 바꾸지 않는다. 해당 처리 URL을 공식 주소로 등록하지 않고, 정확 기관 경계 밖의 처리 주소는 계속 미확인으로 남긴다. 이 힌트로 안전 판정을 허용하지 않으며 미확인 검색에 대해 사칭/외부 전송 위험을 단정하던 표시를 줄이는 것이 목적이다. 실제 스크립트·서버 처리·제출을 실행하지 않는다. TLS 중계/원본 구분과 카탈로그는 불변이다.

선택 컨트롤 모델 참고: https://html.spec.whatwg.org/multipage/form-elements.html#the-select-element . 입력 목적과 예외 한도는 앱의 제한적 휴리스틱이며 HTML 표준이 보안성을 인증한다는 뜻이 아니다.

새 회귀24개(긍정4/제외19/별도 위험폼 보존1) 추가. 관련88개0.34초, 전체 로컬776개42.91초 통과(기존 Starlette/httpx 사용중단예정 경고1). 저장된 달성군 원본 HTML 재분석에서3개 same_origin_search=true/search_only=false, unexecuted_code=true를 확인했다. 완료 원자료를 재수집하거나 카탈로그를 수정하지 않았다.

VM 배포 첫 시도는 Brev publickey 인증 실패로 원격 명령 실행에 도달하지 못했다. 최종 배포·실측 결과는 아래 및 docs/evidence/2026-09-26-search-selectors.json에 별도 기록한다.

최종 배포 상태(2026-09-26 03:24 UTC): 미반영. 네 차례 배포 연결 모두 Brev 게이트웨이의 Permission denied(publickey)로 명령 실행 전에 거절됐다. brev ls는 RUNNING/COMPLETED/READY, healthcheck는 Healthy. refresh는 성공했지만 접속은 복구되지 않았다. 첫 SSO는 브라우저 응답 지연으로 대기 만료됐고, 새 요청은 기존 Chrome NVIDIA 세션에서 로그인 완료됐다. 재인증 이후에도 SSH 연결이 거절됐다. CLI가 새 SSH 사용자 인증서를 발급한 파일 시각과 인증서 유효구간을 확인했으며, 해당 접속 시도는 유효구간 내였다. 인증서/키 본문·인증 URL은 이 기록에 저장하지 않는다. 인스턴스 초기화·재시작·SSH 신뢰 설정 변경·접근권한 확대는 하지 않았다.

이번 수정은 로컬만 완료: 전체776개/관련88개 통과. VM의 전체752개 결과와 달성군 자료 단계31개1.69초는 이전 결과다. 새 VM 테스트/샌드박스 업로드/실제 주소 재검증은 미실행이며, 서비스에는 기존 검색 분류가 남아 있다. 카탈로그는22,120레코드/16,282호스트, 제외2,415(미제공2,388+기타27), 보건미제공30/보완165/inactive0 그대로다.

재개 지점: docs/evidence/2026-09-26-search-selectors.json의 두 파일 before/after 해시를 비교하고 새 변경을 보존해야 한다. /tmp/deploy_search_selectors.py는 원격 이전 해시 확인 후 두 파일만 반영→VM 전체검사→샌드박스 업로드하는 준비된 배포 절차다. SSH 복구/환경변화가 없으면 동일 배포·SSO 재시도를 반복하지 않는다. 연결 복구 뒤 샌드박스 파일 해시/긍정·위험 혼합 사례와 달성군 실제 주소를 검증하고, 새 결과는 카탈로그 단계 실측과 구분해 기록한다. 기관 자료 연구 등 SSH와 무관한 남은 작업은 이어갈 수 있다.
