# 사이트별 예외 없이 주소를 조사하는 구조

## 동작

- Public Suffix List의 PRIVATE 영역을 포함해 주소의 등록 경계를 분석한다. 임의 하위 주소도 같은 방식으로 분석하며, 공유 호스팅의 서로 다른 사용자 주소는 분리한다. 같은 등록 경계는 운영 주체나 페이지 안전성의 보증이 아니다.
- 운영 조사에서는 최초 주소 하나만 열고 시작한다. HTTP 이동으로 새 호스트를 발견하면 호스트 측 중개 코드가 경로 연결, URL 형식, 인증정보, 포트, DNS의 모든 응답을 검사한다. DNS 실패·혼합 공인/사설 응답·IP 리터럴·내부 주소는 승인하지 않는다.
- 정확한 호스트와 확인된 공인 IP를 `allowed_ips`로 제한해 정책을 다시 만든다. Python의 GET, 80/443만 허용한다. 모델은 정책을 수정하지 않는다. 검사 스크립트만 재실행하며 최대 5회 확장, 총 6개 호스트로 제한한다. 확장 루프는 90초 예산을 확인하고 개별 외부 명령에도 시간 제한을 건다. 정리/정책 제어 시간까지 포함한 전체 조사 90초를 보장하는 것은 아니다.
- OpenShell 내부는 직접 DNS가 막혀 있으므로, 호스트의 사전 검사와 프록시의 IP 허용 목록을 함께 사용한다. 기존 정책 제거를 확인한 뒤 교체하고, 성공·실패·시간 초과 모두 finally에서 최종 제거 여부를 확인한다.
- URL만 입력하면 모델로 기관·목적을 추측하지 않는다. 출처 자료를 정확 주소로 조회하고 격리된 검사 스크립트를 직접 실행한다. 문자 입력은 기존 기관·목적 분석을 유지한다.

## 출처와 페이지 위험 분리

`kb/site_catalog.json`은 코드의 사이트별 조건문이 아닌, 다시 생성 가능한 출처 자료다. 정부24·ALIO·나이스·대학/보건기관 표준 데이터·공공병원 명부와 한국 카테고리별 인기 자료를 정규화했다. 앱은 16,505개 자료 레코드, 13,530개 호스트를 조회한다. 인기 자료는 중복 등록 경계를 제거해 1,000개를 선정했다. 공식 자료와 인기 등재를 구분하고, 인기 등재만으로 공식/안전 신호를 주지 않는다.

공식 명부에 나온 정확 호스트를 확인하며, 한 호스트에 여러 기관의 경로가 있으면 URL 경로·질의까지 대조한다. 학교의 상위 도메인이나 형제 학교로 공식 신원을 확장하지 않는다. 같은 등록 도메인 안에서 다른 학교로 폼을 보내거나 코드를 불러오는 경우도 구분한다. 원자료에 홈페이지가 없거나 유효하지 않은 661건은 제외 사유와 함께 `kb/sources/coverage.json`에 남겼다. 유치원 별도 명부 등 범위 누락은 남아 있으므로 공공기관 전체 완료를 뜻하지 않는다.

출처 확인일이 90일을 넘긴 카탈로그 자료는 공식 확인에 쓰지 않는다. 새 자료 파일이 생성되면 주소/문자 조회 때 변경 시각에 따라 다시 읽는다. 관찰한 이동 관계는 별도 SQLite 자료에 호스트 쌍만 저장하고 24시간 후 조회 대상에서 제외한다. 질의 문자열·토큰·페이지 본문·이전 안전 판정은 이 관계 자료에 저장하지 않는다. 이동 관계는 참고 정보이며 공식 신원이나 차후 접속 허가를 부여하지 않는다.

화면에는 주소 관계, 공식 여부, 페이지 행동, 암호화 연결을 분리해 표시한다. 확인 자료에 없는 주소를 다른 사람의 사이트라고 단정하지 않는다. TLS 피어 인증서의 발급자·유효기간·DNS 이름·지문·프로토콜을 기록하되 중계 환경에서 실제 원본 사이트의 신원을 확인했다는 의미로 표시하지 않는다.

## 공식 서비스 디렉터리 및 실제 검증 후 정정

- 파파고의 이전 검사는 HTTP 200/TLS 성공이었지만 주소 근거가 없었다. 네이버 기업사이트 `https://www.navercorp.com/service/all` 및 `/service/portal`의 서비스 홈페이지 연결 76건을 재현 수집기로 추출해 공식 출처 인덱스에 반영했다. 카탈로그는 16,581개 레코드/13,599개 호스트이며 인기 선정 1,000개는 그대로다. 앱의 판단 코드에 파파고나 네이버만을 위한 호스트 조건문을 추가하지 않았다. 발행자와 수집 위치/선택자는 검토 가능한 데이터다.
- 파파고의 새 실제 검사 `j_a687a680325046d798caced4471eae04`, 브라우저 `j_1ee431bdf103480c852a45b1f568ab79`: HTTP 200, 공식 신원 verified, 공식 출처 링크 표시. 실행 후 동작 미검사는 공식 주소 미확인과 구분한다. 내부 verdict unknown이더라도 화면에 '네이버 파파고 공식 주소로 확인됐어요'를 표시한다. 공식 하위 호스트와 등록 경계를 문자열로만 비교하던 잘못된 비교 상자도 수정했다.
- **정책 잔여 검증 정정**: 이전 검사기는 `job-*`만 찾아 NemoClaw의 `nemoclaw_custom__job-*`를 놓쳤다. 11개 이전 정책을 발견해 실제 제거하고, 이름 정규화/시작 시 제거/검사 스크립트와 회귀 테스트를 보강했다. 이전의 잔여 0 주장을 유효한 검증으로 취급하지 않는다.
- NemoClaw 사용자 프리셋은 `allowed_ips`를 거절한다. 공인 IP 제한을 포기하지 않고 OpenShell 네이티브 policy set/update로 적용 및 실제 정책 일치를 검증한다.
- 네이버 대표 주소는 CDN 공인 DNS 응답이 호스트/프록시 사이에 달라 403이 발생했다. 호스트별 1회, 독립 DNS 확인으로 새 공인 IP가 발견된 경우에만 제한적으로 갱신한다. 이미 아는 IP만 나오거나 사설 응답이면 확장하지 않는다. 프록시 오류 메시지에 나온 IP를 승인 근거로 쓰지 않는다. 라이브 결과는 진행 기록에서 확인한다.
- httpcore가 노출한 CPython SSL 객체는 `getpeercert`의 DER 플래그가 위치 인자 전용이다. 키워드 호출 때문에 상세 정보가 누락되던 오류를 수정했다. 연결 피어 메타데이터이며 원본 운영사 신원 확인이나 CT/폐기 검사라는 뜻은 아니다.

## 공식 홈페이지 이동·검색창 오탐·유치원 보완

후속 구현은 검증된 서비스 홈페이지 자체에서 시작해 루트→루트 HTTPS 이동을 별도 수집한다. 공인 IP로 연결을 고정하고 원래 Host/SNI로 인증서를 검증하며 같은 PSL 등록 경계와 정확 URL 범위만 24시간 인정한다. 이름이 www/m이라는 이유로 승인하지 않는다. 공식 홈페이지 이동 7건을 확보했다. 초기 인기 후보가 검증된 최종 후보를 가리던 우선순위도 수정했다.

일반 관찰 캐시는 여전히 신원 근거가 아니다. 검색 역할·GET·검색 입력란만 있고 같은 등록 경계로 보내는 폼은 민감정보 유출로 단정하지 않으며, 별도 미검증 항목으로 남긴다. 비밀번호/POST/다른 등록 경계/제출 버튼 메서드 변경에는 적용하지 않는다.

naver.com/www.naver.com/m.naver.com/papago.naver.com 네 가지 실환경 검사가 모두 HTTP200·차단0·공식 신원 verified로 끝났다. root 검사에서는 CDN DNS 갱신도 실제 실행됐다. `docs/evidence/2026-09-25-canonical-services.json`에 근거를 저장했다. 브라우저에서 동일 결과와 공식 출처 링크 확인. 로컬 전체503개 및 유치원 추가 대상21개 통과.

유치원 알리미 최신2026년1차 전국 일반현황7,152행을 수집하고 유효 홈페이지5,208행을 반영했다. 원장/대표자 이름·전화·상세주소는 정규화 자료에 보관하지 않는다. 최종 카탈로그21,792레코드/16,135호스트, 제외2,605행이며 인기 선정은1,000개 유지. 제외·폐지·주소 변경·공식자료 누락이 남아 있어 전체 기관 완료가 아니다.

최종 VM에 유치원 자료와 수집기·인덱스·회귀 검사를 배포하고 카탈로그를 재생성했다. 전체505개 테스트 통과(67.17초, 기존 httpx/Starlette 사용 중단 예정 경고1개). 위 단계별 수치들은 당시 기록이며 현재 등록 수와 남은 범위는 `2026-09-25-catalog-progress.md`를 기준으로 한다.
